# 블로그 리디자인 설계

2026년 7월 17일 확정. 시안 아티팩트: https://claude.ai/code/artifact/0fd2f9c2-6a81-4ac0-ac21-2dee7df2d59b

2026년 7월 17일 외부 디자인 리뷰(판정: 수정 후 구현)를 받아 워드마크, 홈 구분, 액센트, 접근성, 목차, 서체 검증 항목을 고쳤다.

## 목표

blog.fruitworld.dev의 정보 밀도와 maxkim-j.github.io의 절제를 참고해 개인 기술 블로그를 재설계한다. 요구사항은 네 가지다. 깔끔할 것, 필요한 정보만 첫 메뉴에 노출할 것, 라이트와 다크 모드를 지원할 것, 장기적으로 영문 전환이 가능할 것.

리서치 대상: blog.fruitworld.dev, maxkim-j.github.io, overreacted.io, antfu.me, paco.me, blog.hoseung.me, evan-moon.github.io, jbee.io, junghyeonsu.com

## 스택 결정: Jekyll에서 Hugo로 이전

- i18n 내장: `post.md`와 `post.en.md` 파일명 규칙으로 언어별 페이지, hreflang, 언어 스위처가 자동 생성된다. Jekyll은 폴리글랏 플러그인이 필요한데 GitHub Pages 기본 빌드가 지원하지 않아 어차피 Actions 전환이 필요했다.
- `hasCJKLanguage = true`로 한글 글자 수 기반 읽기 시간 계산이 정확하다.
- 태그, RSS, sitemap 내장. 단일 바이너리. 빌드 수 ms.
- 배포는 GitHub Actions 공식 Hugo 워크플로우(`actions/deploy-pages`)로 전환한다.
- 테마를 임포트하지 않고 `layouts/`를 직접 작성한다. 지금처럼 완전히 통제한다.

## 디자인 원칙

1. **같은 정보를 두 번 보여주지 않는다.** 이 원칙이 구조 결정 대부분을 만들었다.
2. **가운뎃점을 쓰지 않는다.** 정보가 나뉘면 줄을 바꾸고, 한 줄 안에서는 쉼표를 쓴다. "2026년 1월 14일, 12분"
3. **언어는 자연스러움 기준.** about, EN, bash처럼 굳어진 것은 영어 소문자로 두고 문장은 한국어로 쓴다. 억지 번역도 억지 영어도 하지 않는다.
4. **모노스페이스는 코드에만.** 날짜와 메타도 본문 서체의 작은 크기로 쓴다.
5. **AI가 만든 티가 나는 장치를 쓰지 않는다.** 번호 매긴 섹션 헤더, 영어 대문자 라벨, 워드마크의 색점, 터미널 커서 흉내, 빈자리를 채우는 문구("연재의 첫 글이에요") 금지.

## 컬러 토큰

녹색 기가 살짝 도는 뉴트럴에 틸 액센트. 두 모드에서 한 색 정체성을 유지한다(다크는 밝힌 틸). 앰버는 다크 모드 노선도의 현재 역 표시에만 쓴다. 액센트는 링크 호버, 연재 표시, 목차의 현재 위치에만 쓰고, 본문 링크는 색만으로 구분하지 않도록 밑줄을 유지한다.

| 역할 | 라이트 | 다크 |
|---|---|---|
| 바탕 | `#fcfdfc` | `#101413` |
| 본문 | `#1c211f` | `#e3e9e6` |
| 보조 텍스트 | `#5e6a65` | `#93a09b` |
| 날짜, 메타 | `#6b7770` | `#7f8a85` |
| 구분선 | `#e4eae7` | `#252c29` |
| 액센트 (링크, 호버) | `#0e7568` | `#52c4b0` |
| 노선도 현재 역 | `#0e7568` | `#d9ad5c` 앰버 |
| 코드 배경 | `#f3f6f5` | `#0b100f` |

코드블록은 각 모드의 톤을 따른다. 라이트에서는 밝은 회녹색 바탕에 얇은 테두리, 다크에서는 짙은 배경. 신택스 하이라이트는 Chroma로 모드별 두 벌을 CSS 변수로 관리한다.

## 서체

| 역할 | 서체 | 크기 |
|---|---|---|
| 글 제목 | Paperlogy | 28px, 700 |
| 본문 소제목 | Paperlogy | 21px, 700 |
| 리스트 글 제목 | Paperlogy | 17px, 700 |
| 본문 | KoPubWorld 돋움 | 16px, 행간 1.85 |
| 설명 한 줄 | KoPubWorld 돋움 | 14px |
| 날짜, 메타 | KoPubWorld 돋움 | 13px |
| 코드 | D2Coding | 13.5px |

- 선정 기준: 가독성이 검증됐을 것, Pretendard처럼 어디서나 보이는 얼굴은 아닐 것.
- 제목 대안은 경기천년제목과 Danjo, 본문 대안은 Wanted Sans와 리디바탕. 근거 사례: evan-moon.github.io가 KoPub 바탕과 Cormorant Garamond 페어링으로 운영 중.
- D2Coding은 한글 주석과 영문 코드의 폭이 2:1이라 정렬이 깨지지 않는다.
- 세 서체 모두 무료이고 셀프호스팅한다(woff2, KS X 1001 기준 서브셋). 폴백은 시스템 한글 폰트.
- 구현 1단계는 세 서체를 실제로 얹은 프로토타입 검증이다. 확인 항목: KoPubWorld 돋움의 3굵기 한계(400과 700 사이 미세 조절 불가), Windows 저해상도 힌팅, 라틴 글리프 품질(날짜와 NAT, TCP 같은 영숫자가 본문에 상시 섞인다). 탈락 시 본문은 Wanted Sans, 제목은 경기천년제목으로 교체.
- 본문 폭 42rem(672px), 한 줄 약 65자. `word-break: keep-all`.

## 사이트 구조

```
/           홈 = 글 목록 (posts 메뉴 없음, 홈이 곧 목록)
/about/     소개
/series/    연재 인덱스 — 모든 연재의 노선도가 한 페이지에 쌓인다 (연재별 개별 페이지 없음, 앵커로 접근)
/tags/네트워크/          태그별 목록 (Hugo taxonomy 자동 생성)
/en/...     영문판 (글이 생기면)
기존 글 URL은 Hugo permalinks 설정으로 동일하게 유지한다.
```

헤더는 여섯 요소가 전부다: 워드마크 "한예빈"(이름 그대로 — .log 접미사는 velog가 퍼뜨린 클리셰라 리뷰에서 폐기), 연재, about, GitHub 아이콘, EN 버튼(번역이 있는 페이지에서만 렌더링), 테마 토글(해/달 아이콘). sticky + 배경 블러 유지.

푸터: 저작권 한 줄, GitHub, RSS.

기존 Archive, Categories, Contact 페이지는 없앤다. Archive의 역할은 홈이, Categories의 역할은 태그 페이지가 담당한다.

## 홈 화면

- 히어로: 이름 "한예빈"을 제목 서체로 크게(24px), 소개는 보조색 두 문장. 예: "클라우드와 네트워크를 공부합니다. 지금은 네트워크 기초 연재를 쓰고 있습니다." 두 번째 문장의 연재 링크가 노선도 페이지의 진입로다. GitHub는 텍스트 링크가 아니라 헤더 아이콘으로 둔다.
- 소개와 글 목록 사이에 구분 장치를 두지 않는다. 스케일 대비(이름 24px 대 목록 제목 17px)와 큰 여백(72px 이상)이 전부다. 참고한 블로그 어디에도 이 둘을 나누는 장치가 없었다.
- 글 목록: 최신순, 글마다 세 줄 구조.
  1. 제목 (Paperlogy, 호버 시 액센트색으로 0.15초 전환. 그 외 효과 없음)
  2. 설명 (front matter `description`. 쓰고 싶은 말이 있을 때만, 길이와 어조 자유 — 전 글이 같은 문형이면 그것도 생성물 냄새다)
  3. 날짜와 읽기 시간 "2026년 1월 14일, 12분"
- 연도 그룹 헤더 없음(날짜에 연도가 이미 있다), 태그 없음(설명이 글의 냄새를 전한다), 연재 카드 없음(소개 문장이 담당).
- 글이 20편을 넘으면 페이지네이션을 붙인다.

## 글 페이지

위에서 아래로:

1. 연재 소속 한 줄(연재 글에만): "**네트워크 기초 연재**의 1편입니다." 연재 이름은 연재 노선도 페이지로 링크.
2. 제목 (Paperlogy 28px)
3. 메타 한 줄: "2026년 1월 14일, 12분"
4. **노선도 목차** — 이 블로그의 시그니처
5. 본문
6. 태그: 쉼표로 구분한 링크 나열
7. 하단 내비게이션: 작은 링크 한 줄. 이전 편이 있으면 왼쪽에 "← 제목", 다음 편이 있으면 오른쪽에 "제목 →" — 라벨 없이 제목만. "목록으로"는 두지 않는다(워드마크가 이미 홈으로 가는 문). 큰 카드를 쓰지 않고, 없는 방향은 만들지 않는다.

### 노선도 (시그니처)

연재와 목차, 두 층위에 같은 시각 문법을 쓴다. 세로 경로에 역(점)이 놓이고 완료는 채워진 점, 예정이나 미도달은 빈 점, 예정 구간은 점선.

- **연재 노선도** (`/series/` 인덱스): 연재가 여러 개 쌓이는 것을 전제로, 한 페이지에 연재마다 이름("네트워크 기초, 3편 중 2편")과 노선도 블록이 세로로 이어진다. 역 하나가 글 하나. 예정인 글은 점선 아래 빈 역으로 "TCP 심화, 쓰는 중"처럼 표시하되, 실제로 초고를 쓰는 동안만 노출하고 멈추면 지운다(박제된 coming soon 방지). 글 페이지의 연재 링크는 이 페이지의 해당 연재 앵커로 간다. 페이지 하단에 태그 목록(태그 이름과 글 수)을 얹어 묶음 탐색을 한 곳으로 모은다.
- **목차 노선도** (글 페이지): 역 하나가 h2 섹션 하나. IntersectionObserver로 현재 섹션을 추적해 지금 읽는 역이 켜지고 지나온 역이 채워진다. 스크린리더에는 `aria-current`로 전달. **읽기 진행 바는 두지 않는다** — 목차가 위치 표시를 겸하므로 중복이다.
- 목차에 테두리 박스와 "목차" 라벨을 씌우지 않는다 — 노선도만. 박스형 TOC는 테마 기본형의 문법이다.
- 1100px 이상에서는 목차가 본문 우측에 고정(sticky), 그 미만에서는 제목 아래 `<details>` 접이식(기본 접힘). h2가 3개 이하인 글은 목차를 생략한다.

### 본문 요소

- 콜아웃: 왼쪽 3px 액센트 선, "**참고** — ..." 형식. Hugo shortcode로 제공.
- 코드블록: 각 모드의 톤(라이트는 밝은 바탕에 테두리), 우상단에 언어 라벨 소문자("bash")와 복사 아이콘. 복사하면 아이콘이 체크 표시로 잠깐 바뀐다.
- 표, 인용, 이미지는 현행 스타일을 톤에 맞게 이식.
- 다이어그램 이미지의 다크 모드 정책: 투명 배경 SVG에 `currentColor` 우선, 안 되면 라이트와 다크 2벌. 흰 배경 PNG를 다크 바탕에 그대로 올리지 않는다.

## 기능 비교에서 채택한 것

다른 블로그에는 있고 시안에 없던 기능을 훑어 다섯 개를 채택했다.

- 글별 OG 메타와 이미지: 기본 OG 이미지 한 장부터. 글별 자동 생성은 나중에.
- 소제목 앵커 링크: h2에 마우스를 올리면 # 이 나타난다.
- 코드 라인 하이라이트: Chroma의 hl_lines.
- 수정일 표시: 고친 글에만 "2026년 3월 2일 고침".
- 각주와 이미지 캡션 스타일.

보류와 제외: 수식과 다이어그램 렌더링(필요한 글이 생기면 KaTeX, Mermaid), 관련 글 추천(연재와 태그가 대신), 공유 버튼, 키보드 이동.

## 인터랙션

- 테마 토글: 기본은 시스템 설정, 클릭 시 localStorage 저장. `<head>` 최상단 인라인 스크립트가 첫 페인트 전에 `data-theme`을 지정해 FOUC를 막는다.
- EN 버튼: Hugo `.Translations`가 비어 있으면 렌더링하지 않는다.
- 모든 전환 효과는 `prefers-reduced-motion`을 따른다.
- 키보드 포커스 스타일 명시.

## i18n 준비 (구조만)

- `defaultContentLanguage = "ko"`, `en` 언어 슬롯 정의.
- UI 문자열은 `i18n/ko.yaml`, `i18n/en.yaml`로 분리.
- 영문 글은 `post.en.md` 파일 추가만으로 `/en/`에 생성되고 hreflang이 자동으로 붙는다.
- 지금은 영문 콘텐츠를 만들지 않는다.

## 마이그레이션

- 기존 글 1편: front matter의 `category: network` → `tags: [네트워크]`, `series: 네트워크 기초` 추가, `description` 작성. URL은 기존 경로 유지.
- About 내용 이식, 404 이식. Archive, Categories, Contact 페이지 제거.
- Jekyll 관련 파일(Gemfile, _config.yml, gemspec) 제거, Hugo 구조로 재편.
- GitHub Actions 워크플로우 교체.

## 넣지 않는 것

- 인터랙티브 다이어그램, 스크롤리텔링: 글 쓰는 비용이 폭증한다.
- 검색: 글이 서른 편쯤 되면 Pagefind를 붙인다.
- 댓글: 필요해지면 giscus 한 줄.
- 조회수, 좋아요: 외부 의존과 동기 왜곡.
- 손그림 도식 표지: 검토 후 제외. 시그니처는 노선도 하나로 충분하다.
- 읽기 진행 바: 노선도 목차가 겸한다.
